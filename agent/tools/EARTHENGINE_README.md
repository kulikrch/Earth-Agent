# EarthEngine MCP-инструменты

`agent/tools/EarthEngine.py` реализует MCP-сервер для работы с Google Earth Engine через REST API. Инструменты используются агентами Earth-Agent для поиска спутниковых сцен, получения metadata и скачивания отдельных каналов в виде GeoTIFF-файлов.

Документ описывает текущее поведение инструментов, правила выбора коллекций и ограничения, которые важно учитывать при агентном анализе данных дистанционного зондирования Земли.

## Назначение

EarthEngine-инструменты закрывают этап получения спутниковых данных. Они не выполняют финальную аналитику сами по себе, а подготавливают входные растры для последующих инструментов `Index`, `Statistics`, `Inversion` и `Analysis`.

Типовой маршрут:

1. Вызвать `list_collections`, чтобы понять доступные коллекции и их назначение.
2. Выбрать физически подходящую коллекцию под задачу.
3. Найти сцены через `search_images` с учетом bbox, дат и облачности.
4. При необходимости проверить сцену через `get_image_metadata`.
5. Скачать один или несколько каналов через `download_band` или `download_bands`.
6. Передать сохраненные GeoTIFF-файлы в инструменты анализа.

Важно: выбор коллекции и каналов не является ответом на вопрос. EarthEngine-инструменты только получают данные. Итоговый вывод строится после расчета индексов и статистик.

## Запуск MCP-сервера

Сервер запускается как отдельный процесс и требует директорию для сохранения выходных файлов:

```powershell
.\.venv\Scripts\python.exe agent\tools\EarthEngine.py --temp_dir evaluate_langchain\run\out
```

Дополнительно можно передать путь к ключу сервисного аккаунта Google Earth Engine:

```powershell
.\.venv\Scripts\python.exe agent\tools\EarthEngine.py --temp_dir evaluate_langchain\run\out --gee_key path\to\service-account.json
```

Если `--gee_key` передан, он имеет приоритет и записывается в переменную окружения процесса. Если параметр не передан, сервер ищет учетные данные в окружении.

## Требования к окружению

Для работы нужны:

- сервисный аккаунт Google Cloud с доступом к Earth Engine;
- путь к JSON-ключу сервисного аккаунта или JSON-ключ в переменной окружения;
- Python-зависимости для авторизации, rasterio, numpy и FastMCP;
- опционально Redis для кэширования повторных запросов;
- опционально matplotlib или Pillow для создания PNG-preview скачанных GeoTIFF.

Секреты и реальные значения ключей не должны храниться в документации или исходном коде.

## Доступные инструменты

### `list_collections`

Возвращает словарь поддерживаемых коллекций с metadata и рекомендациями по применению.

Используется первым, чтобы агент выбрал коллекцию по физическому смыслу задачи.

Возвращаемые сведения включают:

- Earth Engine collection ID;
- человекочитаемое название;
- пространственное разрешение;
- частоту повторного наблюдения;
- список каналов;
- свойство облачности;
- типичные сценарии применения;
- ограничения коллекции;
- типовые соответствия каналов для NDVI, NDBI, NDWI, LST и других задач.

### `search_images`

Ищет спутниковые сцены в выбранной коллекции.

Основные параметры:

| Параметр | Смысл |
|---|---|
| `collection` | Alias коллекции, например `sentinel2`, `landsat8`, `landsat9`, `hls_landsat`, или полный Earth Engine ID |
| `bbox` | Границы области `[min_lon, min_lat, max_lon, max_lat]` |
| `start_date` | Начало периода в формате `YYYY-MM-DD` |
| `end_date` | Конец периода в формате `YYYY-MM-DD` |
| `cloud_cover_max` | Максимально допустимая облачность, по умолчанию 20% |
| `limit` | Максимальное число сцен в ответе |

Инструмент возвращает список сцен с ID, датой, облачностью и списком доступных каналов. Список сортируется по облачности.

Рекомендации:

- если вопрос задает контрольную дату, сначала искать узкое окно вокруг этой даты;
- при сравнении периодов сохранять одну коллекцию и сопоставимый сезон;
- если сцен нет, сначала расширять временное окно или облачность, а не менять физический смысл данных;
- для multi-year сравнения не выбирать случайно самый малооблачный снимок за весь год, если это нарушает сезонность.

### `get_image_metadata`

Возвращает подробную metadata конкретной сцены.

Используется для проверки:

- доступных каналов;
- типа данных;
- CRS и grid;
- footprint сцены;
- свойств изображения.

Этот инструмент полезен, когда `download_band` сообщает, что канал не найден, или когда нужно подтвердить наличие теплового канала, SWIR, NIR и т.д.

### `download_band`

Скачивает один канал сцены в GeoTIFF.

Основные параметры:

| Параметр | Смысл |
|---|---|
| `image_id` | Полный ID сцены Earth Engine |
| `band_name` | Имя канала |
| `bbox` | Границы скачиваемой области |
| `output_path` | Относительный путь внутри `TEMP_DIR` |
| `resolution` | Желаемое разрешение в метрах |

Инструмент возвращает строку вида:

```text
Result saved at <absolute_path_to_tif>
```

После скачивания создается GeoTIFF и, если доступен backend, PNG-preview рядом с ним. Сначала пробуется matplotlib, при его отсутствии используется Pillow.

### `download_bands`

Скачивает несколько каналов одной сцены. Это предпочтительный способ, если для дальнейшего анализа нужны согласованные каналы с одной даты и одного сенсора.

Требования:

- `band_names` и `output_paths` должны иметь одинаковую длину;
- порядок выходных файлов соответствует порядку каналов;
- каналы должны принадлежать одной сцене.

Использовать этот инструмент удобно для:

- NDVI: NIR + Red;
- NDBI: SWIR + NIR;
- NDWI: Green + NIR или другая выбранная пара;
- LST/теплового анализа: тепловой канал Landsat Collection 2;
- оптических water proxy: видимые каналы, если они соответствуют методике.

## Поддерживаемые коллекции

| Alias | Earth Engine ID | Разрешение | Основное применение | Важные ограничения |
|---|---|---:|---|---|
| `sentinel2` | `COPERNICUS/S2_SR_HARMONIZED` | 10 м | Детальная городская, растительная и водная оптика | Нет теплового LST-канала; B10 - cirrus, B11/B12 - SWIR |
| `landsat8` | `LANDSAT/LC08/C02/T1_L2` | 30 м | Исторический анализ, LST, тепловой остров | Повторяемость около 16 дней, грубее Sentinel-2 |
| `landsat9` | `LANDSAT/LC09/C02/T1_L2` | 30 м | Новые данные с 2021 года, LST, продолжение Landsat 8 | Короткий архив |
| `hls_landsat` | `NASA/HLS/HLSL30/v002` | 30 м | Гармонизированные временные ряды Landsat | Не заменяет native Sentinel-2 для задач, где важны 10 м |
| `hls_sentinel` | `NASA/HLS/HLSS30/v002` | 30 м | Гармонизированные Sentinel-like временные ряды | Данные приведены к 30 м; B10 не тепловой |
| `modis` | `MODIS/006/MOD09A1` | 500 м | Крупномасштабный региональный/континентальный анализ | Непригоден для детального городского анализа |

## Правила выбора коллекций и каналов

Выбор должен идти от физического смысла задачи.

| Задача | Типичные каналы/коллекции |
|---|---|
| Растительность, NDVI | NIR + Red, например Sentinel-2 `B8` + `B4`, Landsat `SR_B5` + `SR_B4`, HLS `B5` + `B4` |
| Застроенные территории, NDBI | SWIR + NIR, например Sentinel-2 `B11` + `B8`, Landsat `SR_B6` + `SR_B5`, HLS `B6` + `B5` |
| Водные объекты, NDWI-like задачи | Green + NIR/SWIR в зависимости от выбранного индекса |
| Оптическая мутность или water-quality proxy | Видимые каналы, обычно Red/Green в соответствии с методикой; не заменять на площадь воды |
| Температура поверхности, тепловой остров | Landsat Collection 2 Level 2 `ST_B10` или другой настоящий thermal/LST-канал |

Критически важно не путать SWIR и thermal. Sentinel-2 `B11` и `B12` - это SWIR-каналы, а не тепловые каналы для LST. Sentinel-2 `B10` - cirrus-канал, а не канал температуры поверхности.

## Работа с путями

`output_path` в `download_band` и `download_bands` задается относительно `TEMP_DIR`, переданного при запуске MCP-сервера. Инструмент возвращает абсолютный путь к сохраненному файлу.

Для последующих инструментов нужно использовать именно путь, возвращенный инструментом, а не вручную сконструированную относительную строку. Это снижает риск ошибок вида `Failed to open question3/file.tif`.

## Кэширование

В EarthEngine-инструментах используется два уровня кэширования:

1. Redis-кэш для metadata, результатов поиска и pixel data.
2. Файловый кэш для уже скачанных GeoTIFF-файлов.

Если Redis недоступен, инструменты продолжают работать, но повторные запросы будут медленнее и будут снова обращаться к Earth Engine.

Подробнее поведение кэша описано в `EARTHENGINE_CACHING.md`.

## Типовые ошибки

### Не найдены credentials

Причина: сервер не получил путь к JSON-ключу или JSON-ключ в окружении.

Решение: передать `--gee_key` при запуске или настроить переменную окружения для ключа сервисного аккаунта.

### Канал не найден

Причина: выбранный `band_name` отсутствует в сцене или перепутана коллекция.

Решение: вызвать `get_image_metadata(image_id)` и проверить список `bands`.

### Нет сцен при поиске

Причина: слишком узкий период, слишком строгая облачность, маленький bbox или неподходящая коллекция.

Решение: расширять ограничения контролируемо: сначала окно дат или облачность, затем альтернативную физически подходящую коллекцию.

### Скачивание слишком медленное

Причина: большой bbox, маленькое значение `resolution`, отсутствие кэша или повторные запросы к API.

Решение: уменьшить bbox, использовать разумное разрешение, включить Redis и переиспользовать файловый кэш.

## Принципы корректного использования агентом

- Сначала выбрать коллекцию по задаче, а не по случайному наличию сцен.
- Сохранять сопоставимость коллекций и сезонов при сравнении годов.
- Не заменять тепловой анализ оптическими каналами.
- Не заменять показатель мутности площадью воды.
- Для нескольких периодов скачивать данные так, чтобы далее можно было получить отдельную статистику по каждому периоду.
- Использовать абсолютные пути, возвращенные инструментами.
- Проверять metadata, если есть сомнение в каналах сцены.
